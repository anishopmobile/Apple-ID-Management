# گزارش تعهد و ویرایشگر متن تعهدنامه

## رابط کاربری
از منوی «گزارشات → گزارش تعهد» وارد مسیر `index.php?route=reports_commitment` شوید. ستون‌های نام مشتری، شماره موبایل و Apple ID، فیلتر آنی سه‌گانه، صفحه‌بندی ۲۵/۵۰/۱۰۰، مرتب‌سازی صعودی/نزولی و PDF هر ردیف، از همان مؤلفه و API آزموده‌شده گزارش Apple ID Card استفاده می‌کنند. حذف منطقی رکوردها محترم است. گزارش جدید API مستقل `reports_commitment_api` و اکشن PDF جداگانه دارد، اما داده‌های اصلی مشترک‌اند.

## متن تعهدنامه
در `index.php?route=settings` بخش «متن تعهدنامه برای گزارش تعهد» فعال است. از ویرایشگر HugeRTE نسخه ثابت 1.0.14 استفاده می‌شود که مستندات Tabler توصیه کرده‌اند. دارایی‌های `themes, skins, icons, models, plugins` همگی در مرحله ساخت، از npm در `public/assets/vendor/hugerte` کپی و در ZIP انتشار بسته‌بندی می‌شوند؛ هیچ فایل CDN در زمان اجرا لازم نیست. دو حالت «ساده» و «پیشرفته» دارند؛ بدون JS هنوز textarea قابل استفاده است. حالت و HTML مجاز در جدول موجود `settings` ذخیره می‌شوند؛ این بخش جدول جدید یا تغییر دیتابیس ندارد.

**امنیت:** متن ورودی حداکثر ۴۸۰۰۰ بایت و حداکثر ۱۰۰۰۰ نویسه است. `src/CommitmentText.php` همه عناصر مخرب، اسکریپت، تصاویر، event attributes، لینک‌های خارجی، جاوااسکریپت، فرم و SVG را حذف کرده، فقط عنوان و پاراگراف، بولد/ایتالیک/زیرخط و فهرست‌ها را به‌صورت محدود نگه می‌دارد. هر تغییر فقط با نشست مدیر و CSRF انجام می‌شود. متن در صفحه بدون رندر HTML ناامن داخل textarea قرار دارد. HTMLِ پاک‌سازی‌شده در mPDF ساخته می‌شود. **هیچ متن تعهدنامه ساختگی جایگزین نمی‌شود:** تا وقتی متن واقعی ثبت نشود، تولید PDF تعهدنامه انجام نمی‌شود.

## صفحه PDF
اندازه PDF **A4 عمودی، ۲۱۰×۲۹۷ میلی‌متر** است. فایل PDF کارت اصلی *بدون تغییر* با ابعاد دقیق ۸۵×۵۵ میلی‌متر و همان قالب گرافیکی در مرکز بالای صفحه به‌صورت **برداری** و از حافظه وارد می‌شود (mPDF/FPDI، بدون عکس گرفتن یا خروجی موقت عمومی). لوگوی موجود سایت ـ اگر ثبت شده باشد ـ در سمت راست بالای صفحه و خارج محدوده کارت قرار می‌گیرد. بعد از خط جداکننده، متن قالب‌بندی‌شده تعهدنامه از سطر ۸۴ میلی‌متر شروع می‌شود. در صورت طولانی بودن متن، محتوا بدون همپوشانی به صفحه A4 بعدی می‌رود.

فایل `commitment-<record-id>.pdf` فقط با POST، مدیر احراز هویت‌شده، شناسه عددی مجاز و CSRF معتبر از داده‌های واقعی همان رکورد ساخته می‌شود. همان تیک موجود «نمایش رمز عبور و پاسخ‌های امنیتی» روی این کارت نیز اعمال می‌شود و پیش‌فرض آن **مخفی** است. پاسخ PDF با `no-store` مستقیماً دانلود می‌شود؛ رمزها و پاسخ‌ها در URL/HTML گزارش یا پوشه عمومی ذخیره نمی‌شوند.

## اصلاح انتخاب تاریخ
استثناهای شمسی با JSON معتبر و یک ورودی مخفی در `#date-exception-form` ارسال می‌شوند. JavaScript فهرست **واقعاً تیک‌خورده‌ها** را به صورت `["12","29"]` یا `[]` ارسال می‌کند. سمت سرور هنوز تمامی شناسه‌ها را با فیلدهای فعال تاریخ تطبیق می‌دهد. بنابراین پاک‌کردن همه تیک‌ها واقعاً `[]` را ذخیره می‌کند، و تاریخ ثبت سیستمی قفل و همیشه شمسی می‌ماند.

## تست و فایل‌ها
- `src/CommitmentText.php`: اعتبارسنجی و پالایش HTML ویرایشگر.
- `src/CommitmentPdf.php`: ترکیب برداری کارت ۸۵×۵۵، لوگوی خصوصی و متن تعهدنامه روی A4.
- `src/SiteSettings.php`: دو فیلد جدید در جدول settings، فرم ویرایشگر و سریال‌سازی درست استثناها.
- `src/AppleIdCardReport.php` و `public/assets/js/apple-id-card.js`: همان نمایش و AJAX برای صفحه جدید.
- `public/index.php`: زیرمنو و مسیرهای مجاز مستقل.
- `public/assets/js/commitment-editor.js`، `public/assets/js/date-exceptions.js`: رابط محلی HugeRTE و ارسال دقیق تیک‌ها.
- `package.json` و `scripts/build-assets.mjs`: بسته‌بندی همه دارایی‌های editor به‌صورت خودمیزبان.
- `tests/commitment_integration.php`، `tests/modal_browser.mjs` و `tests/smoke.sh`: پالایش ضد XSS، PDF واقعی A4، متن فارسی، سنجش اندازه، جاسازی فونت، صفحه‌بندی، جستجو، انتخاب تیک و ممنوعیت دسترسی غیرمجاز.

در توسعه `npm install && npm run build:assets` فایل‌های مرورگر را می‌سازد؛ بسته ZIP ساخته‌شده توسط CI همه فایل‌های لازم را دارد و روی هاست نیازی به npm نیست.
