# Apple ID Management | آنی شاپ

پنل خصوصی و فارسی مدیریت اطلاعات Apple ID مشتریان با PHP 8.2+، MySQL، HTML، CSS، JavaScript و AJAX. فقط بخش مدیریت دارد. تاریخ‌ها در رابط شمسی هستند، طراحی بر پایه Tabler RTL با فونت Vazirmatn انجام شده است.

## دریافت نسخه آماده نصب بدون Composer و npm در مقصد

✅ GitHub Actions به‌صورت خودکار پس از هر Push روی شاخه main یا اجرای دستی از Actions:

1. PHP lint و JavaScript syntax، تست نصب روی MySQL 8، ورود، CSRF، داشبورد، تولید PDF فارسی و Excel را اجرا می‌کند.
2. **فقط پس از موفقیت تست‌ها** و با یک checkout تمیز، Composer را با گزینه --no-dev اجرا کرده و npm را نصب و فایل‌های Tabler RTL، Vazirmatn، ApexCharts و تقویم فارسی را محلی‌سازی می‌کند.
3. بستهٔ نصب ZIP شامل public، src، vendor کامل PHP، فونت‌های PDF در storage/fonts و راهنمای INSTALL-FA.md می‌سازد؛ node_modules، تست‌ها، فایل config.php، قفل نصب، سشن‌ها و اسرار را وارد بسته نمی‌کند.
4. فایل zip اصلی، فایل SHA-256 و گزارش JSON را در **Actions → اجرای سبز موفق → Artifacts → apple-id-management-ready-<SHA>** قرار می‌دهد (نگهداری ۳۰ روزه).

برای دانلود ابتدا فایل ZIP متعلق به GitHub Actions را دریافت و باز کنید؛ داخل آن ZIP اصلی قابل انتقال به هاست/ویندوز وجود دارد. فایل اصلی را استخراج کنید. روی مقصد **هیچ فرمان composer یا npm لازم نیست**؛ فقط PHP، افزونه‌های مورد نیاز، وب‌سرور و MySQL باید از قبل نصب باشند. برای نصب روی ویندوز/XAMPP، هاست اشتراکی و بررسی checksum، راهنمای **INSTALL-FA.md** را بخوانید.

با هر commit جدید، فایل artifact نسخه همان commit تولید می‌شود؛ این بسته **ZIP کد قابل اجرا است، نه نصب‌کننده ویندوز و نه بستهٔ PHP/MySQL**.

## امکانات فاز نخست

- نصب دو مرحله‌ای با تست AJAX اتصال MySQL، پیام فارسی خطا، فعال شدن مرحله مدیر فقط در صورت موفقیت.
- ذخیره تنظیمات دیتابیس به شکل محرمانه در storage/config.php خارج از DocumentRoot با سطح دسترسی 0600؛ قفل نصب و تلاش برای حذف فیزیکی public/install.php پس از نصب.
- ساخت مدیر با رمز عبور هش‌شده Argon2id یا bcrypt و صفحه ورود با محدودسازی ورود ناموفق، CSRF، نشست ایمن و کوکی «مرا به خاطر بسپار» ۷روزه (توکن هش‌شده و چرخشی).
- داشبورد تعداد مشتریان/رکوردها، نمودار خطی ۱۴روزه، فهرست آخرین رکوردها، سایدبار ریسپانسیو شامل ثبت اطلاعات، مدیریت مشتریان، گزارشات، تنظیمات و پشتیبان‌گیری.
- بخش «ثبت اطلاعات» اکنون با دو زیرمنوی **ایجاد فیلد** و **ایجاد رکورد** فعال است: تعریف هشت نوع فیلد پویا، Modal ثبت/ویرایش/حذف منطقی، فیلتر ترکیبی، مرتب‌سازی، صفحه‌بندی واقعی، تشخیص مشتری یکتا و ورود/خروجی XLSX امن.
- مدیریت مشتریان مستقل، گزارشات پیشرفته، تنظیمات و پشتیبان‌گیری/بازیابی هنوز صفحات اولیه هستند و در فازهای بعدی کامل می‌شوند.
- [راهنمای دقیق معماری فیلدها، مهاجرت دیتابیس و اکسل](docs/RECORDS-FA.md)

## ارتقای نصب‌های قبلی برای سیستم فیلدهای پویا

پس از جایگزینی فایل‌های برنامه، با اولین بازدید مدیر از /index.php?route=records_fields، جداول افزوده (record_fields، record_values، customer_mobile_keys، record_deletions و record_meta) ساخته می‌شوند. جداول قدیمی customers و apple_records حذف یا بازسازی نمی‌شوند. برای مهاجرت اولیه، کاربر MySQL باید مجوز CREATE داشته باشد.

پیش از ارتقا، **پشتیبان رمزنگاری‌شده از دیتابیس و storage اصلی** تهیه کنید. فایل storage/config.php و installed.lock را از نسخه قبلی نگه دارید و هنگام ارتقا public/install.php بسته جدید را روی سایت فعال قرار ندهید. بررسی شماره‌های موبایل قدیمی ممکن است در صورت وجود مشتریان دارای موبایل تکراری پس از نرمال‌سازی، با پیغام اصلاح اطلاعات متوقف شود؛ داده‌ای به‌صورت خودکار حذف نمی‌شود. جزئیات در [docs/RECORDS-FA.md](docs/RECORDS-FA.md) ثبت شده است.

## نصب و راه‌اندازی

1. سرور با PHP 8.2+ و افزونه‌های pdo_mysql، mbstring، gd، zip، xml، intl، MySQL 8، Composer، Node.js 20+ و npm آماده باشد. یک دیتابیس از قبل ساخته شده و حساب MySQL دارای مجوزهای CREATE، SELECT، INSERT، UPDATE و DELETE لازم است.
2. **فقط اگر سورس پروژه را برای توسعه محلی clone کرده‌اید (نه بستهٔ آماده Actions)** در ریشه پروژه اجرا کنید:

       composer install --no-dev --prefer-dist --optimize-autoloader
       npm install --ignore-scripts
       npm run build:assets

3. **DocumentRoot وب‌سرور را فقط پوشه public قرار دهید.** پوشه‌های src، storage، vendor و فایل‌های کانفیگ نباید از وب قابل دسترسی باشند. روی سرور عمومی HTTPS اجباری است؛ برنامه به‌صورت پیش‌فرض درخواست HTTP غیرمحلی را رد می‌کند. اگر TLS در Reverse Proxy خاتمه می‌یابد، در تنظیمات امن وب‌سرور مقدار HTTPS را برای درخواست‌های اعتبارسنجی‌شده به PHP منتقل کنید، نه با اعتماد کورکورانه به هدرهای ارسالی کاربر. PHP نباید در مسیر دارایی‌ها اجرا شود.
4. به کاربر اجرای PHP اجازهٔ نوشتن در storage و اجازهٔ حذف public/install.php بدهید. پس از راه‌اندازی دسترسی نوشتن public را محدود کنید.
5. مرورگر را باز کنید؛ ابتدا تنظیمات MySQL و سپس مشخصات مدیر را ثبت نمایید.
6. پس از اتمام مطمئن شوید public/install.php حذف شده و storage/config.php و storage/installed.lock ایجاد شده‌اند. اگر حذف فایل نصاب به دلیل مجوز فایل ناموفق بود، آن را **دستی** حذف کنید. قفل مستقل حتی در این حالت مانع نصب دوباره می‌شود.

## کتابخانه‌های محلی

- Tabler RTL نسخه 1.4.0، ApexCharts نسخه 4.7.0، jQuery نسخه 3.7.1، Vazirmatn نسخه 33.0.3 از npm و اسکریپت build-assets به فایل‌های محلی public/assets/vendor تبدیل می‌شوند؛ HTML هیچ آدرس CDN ندارد.
- Persian Date و Persian Datepicker نسخه 1.2.0 برای فیلدهای تقویم در فاز بعد ذخیره می‌شوند. Persian Datepicker قدیمی است و پیش از استفادهٔ بعدی باید از نظر امنیت و سازگاری بررسی گردد.
- hcg-searchable-select به شکل فایل CSS/JS داخل پروژه و JDF 2.70 با مجوز LGPL به‌شکل src/vendor/jdf.php در پروژه قرار دارند.
- mPDF (برای PDF فارسی با فونت TTF وزیرمتن و شکل‌دهی متن راست‌به‌چپ) و PhpSpreadsheet نسخه امنیتی 5.10+ (برای Excel راست‌چین) در Composer نصب می‌شوند. سرویس داخلی src/ExportService.php برای تولید جدول PDF و Excel موجود است و با tests/exports.php آزمایش می‌شود؛ هنوز هیچ دکمه خروجی عمومی در فاز اول فعال نیست.
- به اینترنت فقط هنگام آماده‌سازی وابستگی‌ها نیاز است؛ تمام فایل‌های مورد استفاده در زمان اجرا **محلی** هستند. پوشه vendor PHP و assetهای تولیدی را همراه نسخه release روی سرور منتقل کنید.

## تست‌های پروژه

Workflow موجود در .github/workflows/ci.yml بر روی GitHub Actions اجرا می‌شود و شامل PHP lint، syntax JavaScript، نصب وابستگی‌ها، ساخت دارایی‌های محلی، آزمون نصب/ورود، منطق مشتریان/فیلدهای پویا، واردات و صادرات XLSX و اعتبارسنجی بسته نهایی است. بسته قابل دانلود تنها وقتی هر دو Job سبز شوند بارگذاری می‌شود.

برای اجرای تست روی محیط **ایزوله و خالی** (نه سرور اصلی):

    bash tests/smoke.sh

توجه: این آزمون عملاً سایت را نصب می‌کند و public/install.php را پاک می‌کند.

## حفاظت از اطلاعات

فایل تنظیمات و کلید محرمانه را به Git commit نکنید و پوشه storage را خارج از دسترس HTTP نگه دارید. رمزهای احتمالی Apple ID مشتریان در فاز فعلی اصلاً ذخیره نمی‌شوند؛ برای فازهای آینده، رمزنگاری داده در حالت ذخیره‌سازی با کلید خارج از دیتابیس و سیاست کنترل دسترسی ضروری خواهد بود. Backupهای احتمالی نیز باید رمزنگاری و خارج از DocumentRoot نگهداری شوند.
